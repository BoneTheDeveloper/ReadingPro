# Dictionary MVP Feature

## Overview

Build a local-first English-to-Vietnamese learner dictionary backed by app-owned data. Runtime lookup, suggest, and quick dictionary translation must use the local database only; provider, Wiktionary, Google Translate, and LLM calls are allowed only in offline draft/review workflows and must not become runtime dependencies.

The MVP is an engineering feature with a representative reviewed fixture set. Large dictionary content growth is follow-up work, not an acceptance blocker for this plan.

## Approved Decisions

| Decision | MVP Choice |
|----------|------------|
| Data model | `DictionaryEntry` -> `DictionarySense` -> `DictionaryTranslation`, plus `DictionaryAlias` and `DictionarySourceAudit`. |
| Migration | Destructively replace the current thin `dictionary_entries` shape; no backfill of test-derived rows. |
| Seed scope | Representative reviewed fixtures covering exact lookup, aliases, phrases, multiple senses, status filtering, and ranking. |
| Seed datasets | 3-tier: `small-test.json` (unit/integration tests, ~25 entries), `common-1000.json` (MVP runtime, 1000 common EN-VI words), `generated-50000.json` (performance benchmark, generated by script, gitignored). |
| Runtime status | Return only `reviewed` or `approved` entries/translations by default. |
| Primary translation | Exactly one `isPrimary = true` translation per `senseId + targetLanguage`. |
| Suggest minimum | Normalized query length `< 2` returns an empty success result and should not fetch on the client. |
| Source label | Store translation provenance; backend maps it to display-ready `sourceLabel`; UI does not duplicate label rules. |
| Miss UX | Return deterministic not-found copy, not a guessed meaning. |

## Data Contract

Dictionary entries are source-language focused. Senses contain learner-facing English meaning details. Translations contain target-language text, ordering, review state, and provenance.

```prisma
model DictionaryTranslation {
  id             String   @id @default(cuid())
  senseId        String
  targetLanguage String   @default("vi")
  translation    String
  isPrimary      Boolean  @default(false)
  rank           Int
  confidence     Float?
  status         String   @default("draft")
  sourceType     String
  sourceName     String?
  reviewedAt     DateTime?
  createdAt      DateTime @default(now())
  updatedAt      DateTime @updatedAt

  sense DictionarySense @relation(fields: [senseId], references: [id], onDelete: Cascade)

  @@index([senseId, targetLanguage, status, isPrimary])
  @@index([targetLanguage, status, rank])
  @@map("dictionary_translations")
}
```

Valid translation statuses are `draft`, `reviewed`, `approved`, and `deprecated`. Valid `sourceType` values are `seed`, `manual`, `provider`, `llm`, and `mixed`. For each `senseId + targetLanguage`, exactly one translation row must have `isPrimary = true`. Seed validation enforces both "at least one" and "at most one"; the database migration should add a unique partial index for the "at most one primary" side.

## API Contract

Routes keep the existing project response envelope and return bounded DTOs, never raw Prisma rows. Translation DTOs expose provenance plus a backend-generated label.

```ts
interface DictionaryTranslationDto {
  id: string;
  senseId: string;
  targetLanguage: "vi";
  translation: string;
  isPrimary: boolean;
  rank: number;
  confidence: number | null;
  status: "draft" | "reviewed" | "approved" | "deprecated";
  sourceType: "seed" | "manual" | "provider" | "llm" | "mixed";
  sourceName: string | null;
  reviewedAt: string | null;
  sourceLabel: string;
}
```

Lookup order is exact headword, exact alias, seeded phrase/candidate match, then deterministic miss. Senses are returned in usage order, and quick translate uses the first entry's first usage-ranked primary translation after the translation cache is checked.

Suggest results include `matchType`, `matchedAlias`, `primaryTranslation`, and `sourceLabel`. Ranking is deterministic: exact headword, exact alias, prefix/phrase candidates, status, frequency rank, usage rank, translation rank/confidence, normalized headword, stable id.

## Acceptance Criteria

- Prisma schema and migration support entries, senses, translations with provenance, aliases, and `DictionarySourceAudit`.
- Seed import loads from configurable dataset file (default: `common-1000.json`) and validates the primary-translation/provenance rules.
- Three seed datasets: `small-test.json` (unit tests), `common-1000.json` (MVP), `generated-50000.json` (benchmark, gitignored, generated by script).
- `/api/dictionary` returns bounded multi-sense DTOs for exact, alias, and phrase hits, and stable miss DTOs for unknown terms.
- `/api/dictionary/suggest` returns empty success data for normalized queries shorter than 2 characters.
- Quick dictionary translation is cache-first, local-only, alias-aware, and deterministic on misses.
- UI renders server DTOs, including backend `sourceLabel`, and never imports generated Prisma dictionary model types.
- Tests cover schema validation, seed validation, lookup, suggest ranking/short-query behavior, quick translation, stale UI responses, and docs.

## Out of Scope

- Runtime provider, Wiktionary, Google Translate, or LLM lookup.
- A large dictionary content milestone.
- Provider-output caching into production dictionary tables.
- Pronunciation/audio, full admin review UI, multilingual targets, and complex morphology.
