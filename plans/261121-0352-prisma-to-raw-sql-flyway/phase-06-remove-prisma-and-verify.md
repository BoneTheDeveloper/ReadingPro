## Implementation Steps

1. Delete the files. Run `pnpm remove @prisma/client @prisma/adapter-pg prisma`, edit the scripts, then run `pnpm install`.
2. Run the trace check:
   - `git grep -Ii prisma -- ':!plans' ':!pnpm-lock.yaml'` must print nothing.
   - `pnpm why @prisma/client prisma` must print nothing.
   - `@better-auth/prisma-adapter` may stay in the lockfile. It is a fixed dependency of `better-auth` itself, not something this app installs or imports. State this in the final report.
3. Run the layer check:
   - `grep -rln "@/server/lib/db" src/server --include='*.ts'` may only list repositories, `profile-repository.ts`, `auth.ts`, the test helpers and the `*.test.ts` files.
   - Services may import only `withTransaction` and `isUniqueViolation`, never `pool`.
   - `auth.ts` is the one allowed `pool` import outside repositories, because Better Auth needs the pool itself.
4. Rebuild from an empty volume: `pnpm db:down -v && pnpm db:up && pnpm db:migrate && pnpm db:info`. This wipes the local volume, so take a `pg_dump` first if it holds dev data worth keeping.
5. Run the full gate: `pnpm typecheck && pnpm lint && pnpm exec knip && pnpm test && pnpm build`.
6. Run the manual smoke checklist against `pnpm dev` with the Docker DB:
   - [ ] Sign in with Google, sign out, sign in again
   - [ ] Import a TEXT passage, a PDF passage and a YouTube passage; each reaches `COMPLETED` and shows its CEFR level
   - [ ] Delete a passage
   - [ ] Generate a QUESTION artifact and a FLASHCARD artifact; save progress and reload
   - [ ] Send a chat message, reload to see the history, then clear it
   - [ ] Translate a selection and save the word; save it again (count goes up)
   - [ ] Create, rename, generate (Pro only) and delete a set; the words return to the default set
   - [ ] Start a review, rate cards, end the review; the due and new counts update
7. Production database: hand the user the command and wait for an explicit go-ahead. Before running anything against a production database, take a `pg_dump` backup, even though its data is not important.
   ```
   docker run --rm -v "$PWD/db/migrations:/flyway/sql:ro" flyway/flyway:11-alpine \
     -url="jdbc:postgresql://<host>:5432/<db>?sslmode=require" -user=<user> -password=<password> migrate
   ```
   It has to target an empty database. Then the user updates `DATABASE_URL` in Vercel if the database changed.
8. Write `reports/verification-report.md` with:
   - the output summaries of steps 2 to 5
   - the smoke checklist results
   - the behavior changes: deleting or updating a missing passage or artifact now returns 404 where it used to return 500
